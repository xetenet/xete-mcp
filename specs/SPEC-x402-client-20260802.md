# SPEC: x402 client support — pay another server's paid MCP tool or HTTP resource, on Solana, under the existing spend cap

Status: SCOPING. No code written. Spec derived from the authoritative specs at
`coinbase/x402@main`, read 2026-08-02, not from memory:
`specs/x402-specification-v2.md`, `specs/transports-v2/mcp.md`,
`specs/transports-v2/http.md`, `specs/schemes/exact/scheme_exact_svm.md`.

## Problem

An agent using xete-mcp can send encrypted messages and settle value with another agent, but
it cannot pay for anything **outside** xete. The ecosystem it lives in is standardising on
x402: a resource server (or another MCP server) answers "payment required", the client
attaches a payment, and the call succeeds. Today our agent simply fails those calls.

Two facts from the spec make this worth doing now rather than later:

1. **x402 has a first-class MCP transport** (`specs/transports-v2/mcp.md`). Payment is
   signalled by a tool result with `isError: true` and a `PaymentRequired` body, and paid by
   retrying with `_meta["x402/payment"]`. We would not be inventing the binding.
2. **On Solana the client's entire job is to build and PARTIALLY SIGN a transaction whose
   fee payer is the facilitator.** That is structurally identical to `xete_alias_claim`,
   where the permit server builds a transaction and this client `partial_sign`s it after
   `txguard.inspect_alias_claim` validates its shape. We have already built, hardened and
   adversarially reviewed that exact pattern.

**And there is a gap in the spec that we are unusually well placed to fill.** The SVM
scheme's "Facilitator Verification Rules (MUST)" — six checks, security-critical — exist to
protect *the facilitator's fee payer*. **Nothing in the spec protects the CLIENT.** The
client is told to build a transaction and sign it; no rule says the client must verify what
it signed. Our repo already has `verify_draft`, an instruction-shape whitelist, and a spend
gate that fires before any signature exists. Applying them here is the differentiator, not
the plumbing.

## Non-goals

1. **NOT the server side.** Making *our* tools payable by other agents (returning
   `isError: true` + `PaymentRequired`, running a facilitator) is a separate, larger product
   with its own trust model. Explicitly out of scope.
2. **NOT EVM.** `exact` has nine chain variants; this covers `scheme_exact_svm` only.
3. **NOT x402 v1.** `x402Version: 2` only. v1 transports exist in the repo
   (`transports-v1/`) and are not supported; a v1 `PaymentRequired` is refused with a
   message naming the version, never silently coerced.
4. **NOT automatic payment.** No tool pays without an explicit caller-supplied ceiling. There
   is no "just pay whatever it asks" mode, and no default that permits a spend.
5. **NOT `upto` or `batch-settlement` schemes.** `exact` only.
6. **NOT a facilitator.** We are strictly a client; we never sponsor or settle for others.

## Interface

```python
# src/xete_mcp/x402.py — new module. No MCP tool decorator here; tools live in server.py.

X402_VERSION = 2

@dataclass(frozen=True)
class PaymentRequirements:
    """One entry of the `accepts` array. EVERY FIELD IS ATTACKER-CHOSEN.

    Parsed, never trusted: `amount` is what the payee wants, `payTo` is where the payee
    wants it, `asset` is which token the payee names. A client that signs these because
    they arrived in the response has verified nothing -- the same defect as feeding
    verify_settlement_tx the draft's own recipient.
    """
    scheme: str                     # MUST be "exact"
    network: str                    # CAIP-2, e.g. "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp"
    amount: str                     # base units, decimal string
    asset: str                      # SPL mint pubkey
    pay_to: str                     # recipient OWNER pubkey (not the ATA)
    max_timeout_seconds: int
    fee_payer: str                  # extra.feePayer -- the facilitator
    memo: str | None                # extra.memo, <=256 bytes UTF-8, else client nonce

def parse_payment_required(body: dict) -> list[PaymentRequirements]: ...
    # Refuses: x402Version != 2; empty/missing `accepts`; unknown scheme; malformed pubkeys.
    # All human-readable text (`error`, `resource.description`) is sanitize_text'd and
    # returned QUARANTINED, never merged into this client's own prose.

def build_exact_svm_payment(
    req: PaymentRequirements,
    payer: Keypair,
    *,
    expect_pay_to: str,             # REQUIRED, from the caller. Never from `req`.
    max_amount_base_units: int,     # REQUIRED. The caller's ceiling for THIS call.
    rpc_url: str,
) -> tuple[str, dict]: ...
    # Returns (base64 partially-signed versioned tx, an itemisation for the caller).
    # Builds EXACTLY: [CB SetLimit, CB SetPrice, TransferChecked, Memo].
    # Calls spendguard.authorize() BEFORE the keypair is touched.

def verify_x402_transaction(
    tx_b64: str,
    req: PaymentRequirements,
    *,
    expect_pay_to: str,
    expect_payer: str,
    max_amount_base_units: int,
) -> VerifyResult: ...

    # Reuses draft.VerifyResult so the pass/fail table renders identically.
```

Two MCP tools in `server.py`:

```python
@mcp.tool()
def xete_x402_inspect(payment_required_json: str) -> str: ...
    # Read-only. Decodes a PaymentRequired, itemises every `accepts` entry in base units AND
    # human units, names the payee and the token, and quarantines the server's prose.
    # SIGNS NOTHING. This is the tool an agent calls to show a human what is being asked.

@mcp.tool()
def xete_x402_pay(
    payment_required_json: str,
    expect_pay_to: str,             # required
    max_amount_base_units: int,     # required, no default
    accepts_index: int = 0,
) -> str: ...
    # Builds, verifies, and partially signs. Returns the base64 payload for the caller to
    # attach as _meta["x402/payment"] or the HTTP payment header.
    # DOES NOT make the resource call itself -- see Open question 3.
```

## Invariants

These become the claim list for the final doubt-driven review.

1. **No signature exists before `spendguard.authorize()` has returned.** Same ordering as
   `pay_herd`, `deposit` and `xete_alias_claim`; the AST tripwire in `test_spendguard.py`
   must classify the new signing site.
2. **The ceiling binds to the amount in the SIGNED TRANSACTION, not to the quoted amount.**
   `spend_charge` already takes the max of quoted / instruction-derived / simulated for the
   claim path, because a server that understates its price must not shrink the number the
   gate checks. Identical rule here.
3. **`payTo` is never taken from the response being verified.** The caller supplies
   `expect_pay_to`; a mismatch is a refusal, not a warning. Without this every check passes
   by construction.
4. **The instruction list is a closed set in a fixed order**, refusing by default:
   `[CB SetLimit, CB SetPrice, TransferChecked, Memo]`, with Lighthouse/Memo optional
   extras allowed ONLY at the positions the spec permits. Anything else refuses. This is
   `draft._instruction_shape` applied to a new layout.
5. **The fee payer is not us.** `req.fee_payer` MUST NOT equal our pubkey, MUST NOT be the
   `authority` or `source` of the TransferChecked. (The spec makes the facilitator check
   this to protect itself; the mirror protects us from sponsoring a stranger's transaction.)
6. **The destination is the derived ATA for `(owner=expect_pay_to, mint=asset)`**, computed
   locally under the selected token program — never read from the response.
7. **The compute-unit price is bounded.** The spec's reference facilitator caps at 5
   lamports/CU; we cap at least as tightly. An unbounded priority fee is real SOL leaving
   the wallet with nothing in the itemisation to show for it — finding `[G14]`, already
   benchmarked on `draft.py`.
8. **Every string from the server is quarantined.** `error`, `resource.description`,
   `extra.memo` are attacker prose reaching an agent; they go through `sanitize_text` and are
   returned under an `untrusted_server_text` key, never merged into this client's sentences.
9. **A partially-signed transaction is treated as MAY-BE-LIVE from the moment it leaves us.**
   Once handed to a facilitator we cannot un-sign it. The spec documents a duplicate-
   settlement race; the same class we fixed tonight on our own path.
10. **No copy on any published surface asserts that xete charges for messaging.** An x402
    tool's docstring necessarily discusses paying for *resources*; `test_copy_compliance.py`
    will flag it and the exemption must be justified as "paying a third party for a
    resource", not silenced.

## Plan

- [ ] **Task 1 — `parse_payment_required` + quarantine.** Pure function, no network, no keys.
      Refuses v1, unknown schemes, malformed pubkeys, missing `accepts`. Prose sanitised.
- [ ] **Task 2 — `xete_x402_inspect` tool.** Read-only, signs nothing. Makes the whole thing
      demonstrable and useful before any money code exists.
- [ ] **Task 3 — ATA derivation + `TransferChecked` construction** for spl-token and
      token-2022. This is the only genuinely new on-chain plumbing; we do native SOL today.
- [ ] **Task 4 — `verify_x402_transaction`.** The client-side mirror of the facilitator's
      MUST-list, built as `draft._instruction_shape` was: closed set, fixed order, refuse by
      default. Written and proven RED against hostile fixtures BEFORE Task 5 exists.
- [ ] **Task 5 — `build_exact_svm_payment`,** gated by `spendguard.authorize()` before the
      keypair is touched, and self-verified through Task 4 before returning.
- [ ] **Task 6 — `xete_x402_pay` tool** + manifest/README/`server.json` copy, through
      `test_copy_compliance.py`.
- [ ] **Task 7 — DDR + fresh-context adversarial review** against the Invariants above, plus
      a hostile-facilitator rig in the shape of `mr_anderson.py`.
